# ADR-083: DB tests run inside workerd with Cloudflare's Vitest plugin

## Status

Implemented

- **Status:** built on `claude/test-performance-review-2e47b5` on 2026-11-06. Amends ADR-064: the
  per-file workerd from `getPlatformProxy` is gone.
- **Context:** the 158 test files that call `createTestDatabase()` each booted a `getPlatformProxy`
  workerd with every binding in `wrangler.jsonc`, replayed 215 migration statements one round trip
  at a time, and then sent every query from Node to that workerd. A full server run took 694 s,
  93% of it inside tests, pegged the host, and failed files that passed alone
  (`whole-tree-window`, `write-scope/evidence`), as ADR-064 had seen.
- **Decision:** `@cloudflare/vitest-plugin` (1.6.0, pinned; it accepts Vitest 5) runs a `d1`
  Vitest project inside one workerd, with storage isolated per test file. The project declares
  only `DB` and `MEDIA_BUCKET`. `vite.config.ts` puts a server test in it when its source names
  `createTestDatabase` or `testing/scope-worlds`, so a new DB test lands there unasked.
  `d1.workerd.setup.ts` applies the migrations with `applyD1Migrations`, which also fills the
  `d1_migrations` ledger as Wrangler does on a deployed database, so the schema check runs for real
  and tests no longer seed or mock it.
- **Measured** (same files, one run at a time): change-store, relationship, member and harness
  tests (111) 56–65 s → 3–4 s; `write-scope/evidence` 68 s → 17 s. A whole-suite time on a quiet
  host is still to take.
- **workerd differences found:**
  - It reports a rejection as unhandled when its handler attaches a microtask later (an awaited
    `return run()`, `expect(...).rejects`), then reports it handled. Node waits for the queue to
    drain. The setup file holds each report for a macrotask and passes on only those still
    unhandled; a genuine unhandled rejection is still reported.
  - Reading `console.warn` back does not return a `vi.spyOn` spy, though the spy records calls.
    Assert on the spy reference.
  - Every `createTestDatabase()` call in a file returns that file's one database; tests keep apart
    by tree.
- **Rejected alternatives:** a migrated template database copied per file, which keeps a workerd
  per file and every query crossing from Node; one shared database for all files, which would
  break tests that count whole tables; `isolate: false`, which eight `vi.mock` files rule out.
- **Consequences:** a migration batch runs in a transaction, where `PRAGMA foreign_keys=OFF` (0030,
  0037) does nothing; on an empty database nothing cascades, so tests are unaffected. The Node
  `server` project keeps Vitest's 5-second default timeout, since its 30 s was for the DB tests.
  `readD1Migrations` reads the `drizzle/*.sql` files rather than the journal, as Wrangler does.
