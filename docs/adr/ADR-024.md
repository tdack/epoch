# ADR-024: A public welcome page, and the paths Access must let through

## Status

Implemented

- **Context:** Every page sat behind Cloudflare Access, so a link to Epoch shared anywhere unfurled as the Access login screen, and a visitor whose token failed validation saw an error from the first API call a page made. The app also still carried the stock Svelte favicon.
- **Decision:** `/welcome` is the one page served without an identified user (`server/auth/public-routes.ts`).
  - **What it shows:** the Epoch mark, name and one line, as a full-window version of the link-preview card, with Open Graph tags pointing at `/brand/og-image.png`. It reads no tree, so there is nothing on it to hide; its load returns only whether someone is signed in. It ships no client code (`csr = false`), so it cannot later grow an API call by accident.
  - **Sign-in is a link to `/` (superseded by ADR-026: it links to `/login`).** Epoch has no login endpoint; following any protected path is what makes Access ask who you are. A signed-in visitor sees "Continue to your trees" instead.
  - **The hook sends a signed-out page load to `/welcome`** (303). API calls keep their 401, client-side data requests are left alone (a redirect would hand them HTML), and only GET and HEAD are redirected. Deny by default is unchanged: the redirect replaces an error, it grants nothing.
  - **Superseded by ADR-026:** *Access must bypass the page and what it loads.* No second, Bypass application is needed any more; one Access application covers only `/login`.
- **Brand assets:** the mark (two partners, their child, faded lines to the generation before) is drawn once in SVG under `static/` and `static/brand/`, and `npm run brand:render` rasterises the PNGs and ICO with the Playwright Chromium used for e2e. `EpochMark.svelte` draws the same geometry in the app.
- **Consequences:** Without the bypass Access still intercepts `/welcome`, which is safe (nothing becomes public) but means shared links unfurl as the Access screen. With the dev bypass on, every request has a user, so the welcome page shows its signed-in state locally; run without `ACCESS_BYPASS_DEV` to see the signed-out one.
