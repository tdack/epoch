# ADR-080: Reports are pages printed by the browser, read through the services the screens use

## Status

Implemented

- **Status:** accepted and built on 2026-10-28 (since deployed). It answers the backlog item
  "Printable reports" with stages 2 to 9 of the reports plan
  ([reports-research.md](../reports-research.md)). Dates in words (ADR-079) were stage 1.

## Context

webtrees and desktop programs make reports as PDFs on the server. Epoch runs on Workers, where a
PDF renderer is heavy, and every report would need its own privacy masking. The owner asked for
print stylesheets for the record pages as well as reports.

## Decision

- **A report is an ordinary page with a print stylesheet.** Readers print or save a PDF from the
  browser. `app.css` has one `@media print` block: no app chrome or buttons, black on white, page
  numbers in `@page` margin boxes, a footer naming the tree, print date and the viewer's role, and
  folded `<details>` opened for the print (`layout/print.ts`). Charts print on a landscape named
  page.
- **No report has its own privacy rules.** Each reads through a service a screen already uses
  (`PersonPageService`, `UnionPageService.getGroupSheet`, `ChartService`, `KinshipService`,
  `EvidenceReadService`, `PlaceService`, `OverviewService`), so a printout never shows more than
  the screen, and every route is in the privacy matrix.
- **The reports** (hub at Research, Reports):
  - About a person: individual summary (the person page), ancestor and descendant narratives
    (Ahnentafel; d'Aboville or Henry numbering; sources as numbered endnotes), relatives list,
    research gaps (completeness by generation and brick walls), evidence summary, interview sheet,
    family book.
  - About a partnership: the family group sheet.
  - Across the tree: source usage, place report with places within, the anniversary calendar.
- **The subject comes with the link.** The person page, the drawer and the partnership page link to
  the hub with `?focus=<person>` or `?union=<partnership>`, which the hub resolves through the same
  visibility check as the member's own person (`TreeService.visiblePerson`, `getUnion`). A missing
  or hidden subject falls back to the member's own person. An app-wide focus person, shared with the
  tree view, was considered and rejected: explicit links say whose reports they are, and reading
  the reports would otherwise move where the tree reopens.
- **An installed iOS app cannot print.** `window.print()` there does nothing and raises no error, so
  `PrintButton` waits for `beforeprint` and, if it does not come within a second, offers to open the
  page in the browser (`requestPrint` in `layout/print.ts`).
- **Narratives follow the neutral model.** A partnership is "married" only with a `MARR` event, an
  adoptive, foster or guardian link is said as such, and a later sentence uses the given name, never
  a pronoun chosen from sex.
- **Bounded reads.** The relatives list walks up a set number of generations, then down from those
  ancestors, through the kin window: one query per generation however many relatives. Unpaginated
  reports stop at a cap with its unit in the name (`MAX_SOURCE_USAGE_CITATIONS`,
  `MAX_PLACE_REPORT_FACTS`) and say so when it is reached.
- **Downloads.** CSV is built in the browser from what the page already has (no new server
  surface; cells starting `= + - @` are quoted against formula injection). The calendar's `.ics` is
  a download, not a subscription, because a calendar app cannot sign in through Cloudflare Access.
- **Wall charts.** A chart page can print on A3 to A0: the drawing is fitted to one sheet and the
  outline is left off. A4 keeps the full width over several pages, because a deep pedigree on one A4
  sheet is too small to read. CSS names no A2 to A0, so those are given in millimetres.
- **The family book tells each person once.** A couple is told under whichever partner comes first,
  and the other partner's entry points there ("told under number 2"); the descendants part points
  to the subject's entry in the ancestors part rather than retelling it, and leaves the subject's
  sources out of its notes.

## Consequences

- No server PDF, so page layout depends on the browser: margin boxes (page numbers) need Chrome
  131 or later, and other browsers print without them.
- `main` and its wrapper print as blocks, because Chrome ignores a forced page break on a flex
  item; the family book relies on it.
- Not built: tiling a wall chart across A4 sheets (the print dialog's poster or PDF tools do it),
  a descendant outline numbering choice on the chart page, and a calendar subscription. The flat
  tree's poster and its PDF are ADR-081; the 3D views still do not print.
