# ADR-042: GEDCOM `@`-escaping is done at build time; the tree name round-trips

## Status

Implemented

- **Status:** complete; built on `fix/gedcom-dialect-and-tree-name` on 2026-10-11 and deployed. No migration. Checked by the escape, model-text, tree-name, note, evidence and injection tests, and by the GEDCOM export sweep.
- **Context:** ADR-040 fixed line injection and deliberately deferred three dialect items (GEDCOM `@`-escaping, 255-character `CONC` wrapping and general C0-control stripping) and the tree-name round trip. Escaping then ran as a post-pass over every serialized line, which cannot tell a model payload from a line kept verbatim from an imported file, so it could neither escape the former reliably nor leave the latter byte-identical.
- **Decision:**
  - **A model text is escaped where its line is built, not in a later pass.** `escapedSingleLine` (`evidence-lines.ts`) escapes a single-line field: the event value, `PLAC`, `CAUS`, `AGE`, `MIME`, `LANG`, `CALN`, `_MARNM`, `NAME`/`TYPE`/`PHRASE` and the name parts, the name-change `NOTE`, and `REFN`. `fieldLines`/`textLines` escape every line of a multi-line field, each `CONT` included. Escaping always doubles a leading `@` (`@@foo` → `@@@foo`), so a value can never be read back as a pointer, and it is applied only to text the model supplies.
  - **Leading-only, in both dialects.** A leading `@` is escaped and unescaped in 5.5.1 as well as 7.0, because a 5.5.1 file can carry the same `@@` text even though the standard never named it. This is the owner's decision; a `@` that is not leading is left as it is.
  - **The dialect post-pass is kept for conversion only.** `toGedcom7Lines`/`toGedcom551Lines` still fold `CONC`, convert dates and rewrite the 5.5.1 structures 7.0 renamed (`restructure7`); their old loop over every line's leading `@` is removed. The `PHRASE`s the conversion itself generates (an unknown `MEDI` kind, a `RELA` word) are escaped at the point they are built.
  - **What is never escaped.** A pointer (`@I1@`), a tag and a `DATE` payload (whose `@#…@` calendar escape belongs to the date dialect). A line kept verbatim from an imported file is written back byte-for-byte.
  - **Import reads the escape from the raw bytes.** A node carries `rawValue` (the value before normalisation) and `isAtEscaped` (whether the raw value began `@@`), stamped in `node.ts` from the bytes, not from the cleaned value, so a control code point the normaliser drops cannot turn a malformed payload into an apparent pointer. Unescaping applies to the owning line and its `CONT`s only, never to a `CONC`, whose `@@` sits mid-text and is not an escape. Pointer classification (`isPointer` in `note-parse.ts` and `evidence-parse.ts`) tests `isAtEscaped` and `rawValue` together, at every place a payload can be a pointer: a note link, a citation's `SOUR`, a source's `REPO` and a repository reference.
  - **The 7.0 forbidden control set is stripped, not escaped.** `stripBannedChars` removes the C0 controls except TAB, LF and CR, DEL, the C1 controls, an unpaired UTF-16 surrogate, and U+FFFE/U+FFFF; TAB is kept, and a valid surrogate pair spells an astral character and is kept whole. The stripping runs on import (normalisation) and on export (every built line).
  - **Backfill parity.** The parser's old-way reader stores the first note's raw value (escape and all) in the `events.notes` column, so `note-backfill.ts` rebuilds the note's line and classifies it exactly as a fresh import would; `@@N1@` (text) and `@N1@` (a pointer) no longer both normalise to `@N1@` before the rebuild.
  - **The tree name round-trips.** Export still writes `1 NOTE Tree: <name>` and no `HEAD.FILE`. Import reads the first `HEAD`-child `NOTE`/`SNOTE` whose first line is `Tree: <name>`: first line only, trimmed, capped at 200 characters, not case-folded. A **post-parse conditional rename** renames only a tree the import created, never one it was given, with precedence explicit user name > embedded `Tree:` > uploaded filename > `HEAD.FILE`. The rename is a version-guarded `UPDATE` (name and version must be what the import saw) and logs one `import_tree_name` change-log row; a concurrent write means it does not land. The queue message carries the naming fields additively, and a message without `isTreeNameExplicit` (queued before this change) is read as explicit, so it never renames its tree.
- **Deferred:** 5.5.1 `CONC` wrapping at 255 bytes. Reviewers found no reader in scope that needs it, so it is recorded as a follow-up rather than done.
- **Parked:** an export audit entry. It does not fit `change_log` (ADR-007), which is scoped to tree content for undo, and the owner does not want that level of accountability or tracing, so a dedicated account-level audit table is deliberately not planned. See the note in `src/routes/api/export/+server.ts`.
- **Accepted residuals:**
  - A preserved (unmodelled) line may carry a lone leading `@`: it is written back exactly as the file had it, so it is not escaped.
  - A 5.5.1 row written before this change whose stored value begins `@@` is unescaped on the next import, which can duplicate a merge key for those pre-existing rows; new imports do not have this.
- **Consequences:** the escaping is now testable where it belongs and kept lines stay byte-identical, which is what ADR-003's no-loss rule needs. The `escapeText` decision (escape only model text, never a pointer, a tag, a date or a kept line) is the single rule every call site follows.
