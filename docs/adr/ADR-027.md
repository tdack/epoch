# ADR-027: One person view, in two frames; the open drawer lives in the query string

## Status

Implemented

- **Context:** the tree's drawer and the person page read one `PersonPageDto` but had grown into two half-editors: each did things the other could not (relative removal, partnership edits and media upload only in the drawer; names, facts, privacy, history, merge and favourites only on the page), and the same data was worded and laid out differently. Architecture-review step E5 was skipped for that reason, since sharing components would have changed one screen's output throughout.
- **Decision:**
  - **One view, deliberately converged.** `PersonView` composes section components in `src/lib/components/person/` (summary, family, names, facts, notes, evidence, media, privacy, history, actions). Each owns its actions and dialogs, and hides what the viewer's role cannot do (`person-permissions.ts`, the same rules as before). The screens were made alike on purpose, so every action exists in both frames.
  - **The one real difference is an input.** Clicking a relative selects in place on the canvas and follows a link on the page. `relativeTarget` (`select` or `link`) carries that, and `PersonLink` renders a `<button>` or an `<a>`. Merge reads it too, to land on the surviving record in the same way. No other per-frame prop exists.
  - **Two layouts.** `page` is two columns on a wide screen (records left; family, privacy and history right), one on a phone. `drawer` is one column of native `<details>`/`<summary>`, with the heading an `<h3>` inside the summary so axe and role queries still see it. Family and Facts start open. Which sections the viewer opened is kept in `localStorage` per section, not per person, behind try/catch.
  - **The drawer belongs in the URL as `person`,** beside `focus`, in `tree-url.ts`; an absent parameter means closed. Opening goes through the tree page's `navigate` and pushes an entry, so Back closes it, a reload keeps it, and a link can be shared. `person` is not among the parameters the load reads, so opening or closing refetches no graph. An unloadable person (a stale link, a deletion) closes the drawer with a replaced entry, so Back cannot return to a drawer that will not open.
  - **Not shallow routing.** Pushing `/trees/x/people/y` with `pushState` would move the path, but the tree page keeps its view in the query string and writes the resolved `focus` back from `page.url`; moving the path would fight that effect and lose depths, toggles and opened stubs.
- **Given up:**
  - The drawer is longer: every section is in it, though most are folded.
  - Relatives look the same on both screens, which changes both: the drawer lost its bordered cards for plain rows, and the page gained trash buttons and add links.
  - The person page's header buttons moved from the right of the name to beside it, and Privacy moved into the right column.
  - A docked side-by-side layout is not built; `PersonView` makes it a third `layout` value rather than another fork.
- **Consequences:** `PersonDrawer` is a frame only (a panel over everything below 1024px, a card docked beside the canvas, which narrows and refits, from 1024px; a width the viewer drags from 384px up from 768px, kept in `localStorage`; Close, Escape, Open full page, focus to the heading on open, focus back to the opening card on close). The page is a breadcrumb and a `PersonView`. No API, DTO or schema changes. Supersedes an earlier decision to leave the drawer and page separate.
