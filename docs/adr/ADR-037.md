# ADR-037: Loosely typed dates are read, offered in standard form, and never block an edit

## Status

Implemented

- **Status:** complete; built on 2026-10-10 and deployed. Checked on the owner's 314-person family file in the dev app: 34 dates standardised in one change and undone, and the 3 unreadable dates listed as findings.
- **Context:** files from other programs hold dates like `3 RD DECEMBER 1996`, `29 JANUAY 1959`, `CIRCA 1937` and `14 AUGUST 1975`. Their meaning is clear, but Epoch could not read most of them, so they did not sort. Worse, the forms refused to save or preview while a date field held unreadable text, even when the date had not been touched. One bad imported date locked the whole fact, name, citation, person or partnership.
- **Decision:**
  - **Read leniently, store as written.** `tidyDateText` (`src/lib/shared/date-tidy.ts`) gives the GEDCOM spelling: it drops ordinals, turns full or misspelt month names into their codes, and turns CIRCA/CA/C. into ABT. `parseDateValue` reads the date as written first and falls back to the tidied form only when that fails. The stored text never changes on import (ADR-003). Misspellings are matched conservatively: a word must keep the month's first three letters and be within two edits of a name five or more letters long. May, June and July match only exactly, so words like `MAYBE` and `JUNK` stay as they are.
  - **Offer, don't impose.** `standardDateText` returns the standard spelling only when it differs from the text and means the same date (same qualifier and bounds). A date field shows it as "Use 3 DEC 1996".
  - **An untouched unreadable date never blocks.** `checkDateEdit(value, saved)` accepts an unreadable date that is unchanged from the saved one, and `DateInput` shows an amber note instead of a red error. Every form that edits a saved date uses it.
  - **Findings and a bulk tidy.** `unreadable_date` (warning) lists every fact or name date Epoch still cannot read, reading the text afresh rather than from the stored columns. The quality page's manager-only "Date spellings" panel previews every date that has a standard form, before and after, and rewrites them as one undoable change (`standardise_dates`), recomputing the stored date columns. It covers facts, names and citation entry dates, 200 per turn. Unreadable and already-standard dates are never touched, so a second run does nothing.
  - **Export** converts through the same tidy, so a 7.0 file writes `3 DEC 1996` rather than keeping the text as a `PHRASE` (ADR-036).
- **Consequences:** rows imported before this keep their stored `UNKNOWN` columns until they are re-saved, standardised or backfilled. `npm run db:backfill:dates` (the dual-date backfill, ADR-004 addendum) now also re-reads every `UNKNOWN` row, so one run gives them sort bounds; a date still unreadable writes nothing. Dates nobody can read (an impossible day, two dates run together) stay as written until a person fixes them.
