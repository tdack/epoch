# ADR-073: PDFs are served inline in a new tab (amends ADR-039)

## Status

Implemented

- **Status:** built on `claude/pdf-document-preview-ux-46075b` on 2026-10-21. No migration.
- **Context:** ADR-039 served a PDF as an attachment, so a collaborator could not read one without saving it. Chrome will not render a PDF under `Content-Security-Policy: sandbox`, which the serve route sets on every response, so inline display needs that header gone for PDFs.
- **Decision:**
  - `mediaServeDecision` serves `application/pdf` as `inline` and says whether to sandbox; the route omits the sandbox CSP for a PDF only. `nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `Referrer-Policy: no-referrer`, `private, no-cache` and the ETag stay, and the manual 304 carries the same headers as the 200. Raster and octet-stream responses are unchanged.
  - The download name comes from the file's `media_items.title` (the uploaded name, or the renamed title), computed at serve time, so a rename needs no extra write. `MediaService.requireRead` returns the title from the row it already loads. `safeDownloadName` keeps the last path segment, drops control characters, quotes and header-unsafe characters, strips leading dots, caps the stem at 100 characters, falls back to `download`, and forces `.pdf`. The header carries an ASCII `filename` and an RFC 5987 `filename*`. The octet-stream attachment keeps its key-derived name: it has no known extension to force.
  - `sniffMediaType` accepts `%PDF-` only at offset 0, after an optional UTF-8 BOM and ASCII whitespace. The old 1024-byte search window let a polyglot pass as a PDF, which matters once the file renders inline. Objects already stored are not re-sniffed.
  - The UI opens a PDF in a new tab (`target="_blank"`), with a Download link kept in the Files preview.
- **Residual risks:** a bug in the browser's PDF engine is reachable by any collaborator who can upload; links inside a PDF can lead anywhere; stored objects uploaded under the looser sniff stay as they are.
- **Rejected alternatives:** embedding in an iframe (needs `X-Frame-Options` relaxed); an in-app pdf.js viewer (deferred); converting `.doc`/`.docx` (not worth the containers and LibreOffice it needs).
