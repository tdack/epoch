# ADR-063: Tree subdomains can be turned off, and D1 keeps what setup made on the zone (extends ADR-057)

## Status

Implemented

- **Status:** built on `feat/setup-subdomains-followups` on 2026-10-19 and deployed. **Migration 0035 adds `install_meta.subdomains`** (nullable text, expand only). `npm run deploy` migrates before it deploys, and setup works without the column until then.
- **Context:** `./setup subdomains` had no way back short of `./setup teardown`, which removes the whole install. Its exclusion routes carry no marker, because the Worker routes API has nothing like a DNS record's comment, so a clone with no manifest kept any it found as `referenced` and never deleted them. Turning the subdomains off would make that worse: the zone leaves the deploy config, which was the only thing a fresh clone read.
- **Decision:**
  - **`./setup subdomains --off`** takes the wildcard route and the tree vars out of `wrangler.deploy.jsonc` and the Workers Builds values first, so no deploy started part-way puts the route back. It then deletes the live wildcard route and removes the `*.<zone>/login` Access destination. The DNS record and the exclusion routes stay, and the settings stay in the manifest with `isActive: false`, so `./setup subdomains` turns trees back on without making them again. It shows a plan, asks before applying, and takes `--plan`.
  - **`--off --remove`** also deletes the record and this install's own exclusion routes, as teardown would, and clears the settings. `--remove` without `--off`, and `--off` with `--zone` or `--reserve`, are usage errors.
  - **D1 keeps the record.** `install_meta.subdomains` holds the zone, the DNS record id, the ids of the exclusion routes this install made (never one it found and kept), and whether the subdomains are on, as JSON. Setup writes it when an apply or `--off` finishes, then reads it back. Values are validated (32-hex ids, a zone name) before they are quoted into the SQL, since `cf d1 query` takes no bind parameters. The app never reads it.
  - **Recovery.** `recoverSubdomainSettings` rebuilds the settings for a manifest that has none, from the deploy config's zone and from D1, read with the manifest's D1 id or, before reconcile has found it, the one in `wrangler.deploy.jsonc` (quietly, since that database may not exist yet). A recorded route counts only while it still exists with no Worker, and its pattern comes from the live route. `./setup` seeds the manifest with it, and teardown uses it when the manifest has no settings, so teardown from a fresh clone removes what this install made, even with the subdomains off.
  - **Before the migration.** A missing column reads as "nothing recorded" and setup relies on the manifest alone. Writing warns and names the migration; it never fails an apply whose changes on the zone are already made.
  - **Teardown items carry their zone id,** so removing a record or route no longer needs the manifest's settings.
  - **`doctor` reads an inactive install as off or part-way,** a warning, and names `./setup subdomains` as the way back on. With no record id (a clone seeded from the config alone) it finds the record by its marker, as teardown does.
- **Rejected alternatives:** a marker in the route pattern (a route matches requests by its pattern, so it cannot carry one); claiming any Worker-less route on a captured host (it could delete a route made by hand for the same host); keeping the record in the manifest alone (a fresh clone has none, and after `--off` the config says nothing either).
- **Consequences:** an install set up before this has nothing in `install_meta.subdomains` until `./setup subdomains` runs once after migration 0035 is deployed; that re-run changes only the Access application and writes the record. A write that matches no `install_meta` row (an adopted install whose row names another id) warns, since the UPDATE itself succeeds. The deployed Worker keeps its tree vars after `--off` until the next deploy, which the hand-off says. A route recorded in D1 and later given a Worker by hand is no longer claimed. The new spike checks for ADR-057's API shapes passed against the live account on 2026-10-19, and `./setup subdomains` recorded its zone, record and routes in D1 the same day.
