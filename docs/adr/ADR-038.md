# ADR-038: The deploy config is tracked

## Status

Superseded by ADR-043 ADR-043 replaced the tracked deploy config.

- **Status:** superseded by ADR-043 on 2026-10-12. Was accepted by the owner on 2026-10-10, superseding the git-ignore decision in the setup plan (ADR-033's config-layout question).
- **Context:** `npm run setup` generates `wrangler.deploy.jsonc` — the tracked `wrangler.jsonc` plus this install's D1 id, Worker name, route, vars and resource names — and the file was git-ignored so the owner's values would stay out of git. That broke push-to-deploy: a fresh clone on the deploy host has no deploy file, and nothing in the remote environment can generate one, since the values it needs are exactly what was withheld. The alternatives all need a Cloudflare API token (Workers Builds secrets) or wrangler auto-provisioning (beta, and it bypasses the setup tool's adopt/marker flow). The repo is private with a single owner, and nothing in the file is a credential: D1 and R2 ids, the Worker name, the Access team domain and the sender address are account-scoped identifiers that are useless without an API token that already has account access — at which point the repo's contents are the least of the problem.
- **Decision:**
  - **`wrangler.deploy.jsonc` is tracked.** `.gitignore` no longer excludes it; a fresh clone can deploy without running setup first.
  - **Setup still regenerates it in place.** The file is a build product of the manifest as much as a config; re-running `npm run setup` rewrites it and shows the diff. Adoption of an existing install reads it for defaults.
  - **The build-field agreement check stays.** The build reads `main` and `assets` from the tracked `wrangler.jsonc` while deploys use the deploy file, so `scripts/deploy-config.mjs` still fails `npm run deploy` when those fields drift apart.
  - **`wrangler.deploy.example.jsonc` is deleted.** The tracked file is its own example.
- **Consequences:** anyone who can clone the repo learns the account's resource ids and the Access team domain — acceptable while the repo is private, but the file belongs on the scrub list if the repo ever goes public. Forks inherit someone else's ids until setup rewrites them. The setup plan's "owner-specific values move out of git" rationale now applies only to `wrangler.jsonc` (placeholders) and `.epoch/` (install state).
