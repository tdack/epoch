# ADR-052: Security audit 2026-10-13, F11 to F18: what was fixed, what was not, and the rules that came out of it

## Status

Implemented

- **Status:** built on `claude/audit-f12-f18` and deployed. No migration. The audit is [security-audit-2026-10-13.md](../security-audit-2026-10-13.md).
- **F11, `workers_dev: true`: won't fix.** The app is deployed on a `workers.dev` hostname while it is under development, and nothing there sits behind Access, so the request degrades to anonymous as the audit says. Revisit when the install moves to a custom domain: set `workers_dev` to `false` in the deploy config then.
- **F12, public-visitor context fails closed (amends ADR-041).** The hook still stamps an anonymous `/api` GET with `PUBLIC_VISITOR`, but `apiHandler` and `treeHandler` now refuse that visitor unless the route's options say `allowPublicVisitor: true`, and `treeHandler` refuses it for any tree other than the public one. The refusal is a **403 with the same body** whether the tree is private or unknown, never a 401 (the client restarts sign-in on a 401, which would push an anonymous visitor into Access) and never a 404. The opt-in is written on each route's GET options only; nothing stops a shared options object carrying it to a write, but the hook stamps the visitor on GET and HEAD alone, so a write never sees one. Both factories register the handlers they return, and `privacy-matrix.test.ts` imports every route module and fails if a GET is not a factory handler, or if its opt-in disagrees with `VISITOR_READS`. The one hand-rolled GET, `media/[...key]`, is named in that test and keeps its own guard (`MediaService.requireRead`).
- **F13, raw SQL in `visibility.ts`.** The event-type lists stay **inline literals, validated** by `literalList` (`/^[A-Z]{3,5}$/`), and are not bound: binding them adds 6 parameters to every visibility predicate and takes `NoteRepository.visibleUseCounts` for an 80-id chunk (98 parameters) past D1's limit of 100. Table aliases cannot be bound, so `ident` accepts only `/^[a-z][a-z0-9_]*$/`. `bound-params.test.ts` compiles the heaviest chunked statements it knows of (notes, tasks, cross-references, source counts) and fails past 100 parameters; the review that followed found `visibleCitationCounts` over the limit at 80 ids for a contributor, so its chunk is now 50 and a real-D1 test covers it. The test lists statements by hand, so a new chunked read with a visibility fragment must be added to it. The offline backfill scripts build SQL text but escape quotes completely and take their identifiers from constants; they are not request-reachable and were left alone.
- **F14, id-lookup helpers take a required `treeId`.** `namesOf`, `namesByIds`, `linksOfSource` and `actorNames` scope in SQL: `person_names` through `individuals`, source links through `sources` and a tree-scoped `repositories` join, and actors to those with a `change_log` row in the tree (not current members, so a removed member's edits still show a name). `namesOf` uses `inTree`, the unary-plus form, so SQLite does not walk the tree index. Rows read for the "names of people" plan sample went from 3 to 6, inside its bound.
- **F15 to F17.** The export download takes its `Content-Type` from `shouldCompress` and never from stored object metadata. `CF_IMAGES_TOKEN` and `CF_ACCOUNT_ID` are gone from the platform env type. The two `new RegExp` calls built from a tree id are a prefix check.
- **F18, CSRF and CORS stay on defaults, now guarded.** `csrf-cors.test.ts` fails if `vite.config.ts` sets `csrf`, `trustedOrigins`, `checkOrigin` or an `origin`, or if any source file names an `access-control-allow-` header. In SvelteKit 3 `csrf.checkOrigin` no longer exists and `trustedOrigins` is the only option.
- **Rejected alternatives:** binding the type lists (parameter limit, above); a 404 for a non-public tree (ADR-041 already answers 403, and `resolveTreeAccess` answers the same for an unknown tree); leaving `treeHandler` open by default and relying on the cross-tree check alone (a future handler that forgot its guard would still show the public tree's private people); scoping `actorNames` to current members.
- **Consequences:** a new GET that a visitor should read needs `allowPublicVisitor: true` and a row in `VISITOR_READS`, or the matrix test fails. A new id-lookup helper needs a `treeId`. Open gaps found on the way are in [backlog.md](../backlog.md).
