# ADR-031: Invitations are emailed; sending never undoes them (amends ADR-016)

## Status

Implemented

- **Context:** ADR-016 left the manager to tell the invitee. Cloudflare Email Sending is now enabled for `epoch.example.com`.
- **Decision:**
  - **Sent through the `EMAIL` `send_email` binding** from `welcome@epoch.example.com` (the binding's `allowed_sender_addresses` names only that address), after the invitation row is saved, on a re-invite too. `MemberService` depends on an `InvitationMailer` interface; the Workers implementation and the HTML/text template live in `server/email/`. The link is the request's origin plus the tree page, so it works on any host.
  - **A send failure never undoes the invitation.** It is logged with the error code and correlation id (no address) and the response carries `wasEmailSent: false`, which the Members page turns into "let them know yourself". With no binding (unit tests, a bare preview) nothing is sent and the answer is the same.
  - **Redemption is unchanged:** still on the invitee's next Access-authenticated request, by the address Access asserts (ADR-016). The email is a courtesy, not a token; it grants nothing, and Access remains a separate gate.
- **Consequences:** Deploying needs the sender domain verified in Email Sending. A message accepted for delivery can still bounce; the app does not learn of that.
