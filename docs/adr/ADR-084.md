# ADR-084: Anonymous public-tree reads need a Turnstile pass (amends ADR-041)

## Status

Implemented

- **Status:** built on `claude/turnstile-public-read` on 2026-11-09. No migration.
- **Context:** the public tree (ADR-041) is read by anyone, and each page costs several D1 reads.
  `PUBLIC_READ_RATE_LIMIT` (ADR-066) caps one address, but not a scraper spread over many
  addresses. Turnstile tokens are single-use, so they cannot be checked on every GET.
- **Decision:**
  - **A challenge, then a pass.** An anonymous request that the hook would serve as the public
    visitor must carry a valid `epoch_pass` cookie. Without one, a page load is sent to
    `/verify?next=…`, and an API GET gets the same 403 as any refused visitor (ADR-052), never a 401,
    which would start a sign-in. The check runs after the rate limit.
  - **`/verify`** is a public page with the Turnstile widget (action `public_read`). Its form action
    calls siteverify from the Worker and requires `success`, the action, and a `hostname` equal to
    the host the form was posted to, so a token solved on `localhost` or another tree host is
    refused. On success it sets `epoch_pass`: an expiry and an HMAC-SHA-256 signature, HttpOnly,
    Secure, SameSite=Lax, host-only, for 24 hours. A tree host (ADR-057) gets its own pass.
  - **Off unless configured.** The gate is on when the Worker has a `TURNSTILE_SITE_KEY` secret. With
    the site key set and `TURNSTILE_SECRET` missing, every anonymous read is refused rather than
    served ungated. Both are Worker secrets, not setup-managed vars, because secrets survive a
    deploy and other installs (the demo, forks) keep working with neither.
  - **The pass key is derived from `TURNSTILE_SECRET`.** Rotating the secret ends every pass.
- **Rejected alternatives:** a WAF managed challenge (not in source, and it would also challenge
  members); checking a token per request (tokens are single-use); a separate pass secret (one more
  secret to set for no gain yet); a `TURNSTILE_HOSTNAMES` allowlist (the request's own host is exact
  and needs no configuration).
- **Consequences:** every new anonymous visitor, including those following the website's link to a
  public sub-tree (ADR-069), solves one challenge a day. Signed-in members and the local dev bypass
  never see it. A pass that expires during client-side navigation makes the next data request fail;
  a reload goes through the challenge. Unit tests cover the pass and the hook. A browser run with a
  real token, against a deployment, is still needed to confirm the end-to-end flow.
