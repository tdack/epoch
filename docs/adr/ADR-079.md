# ADR-079: Dates are shown in words, in a format each tree chooses

## Status

Implemented

- **Status:** accepted and built on 2026-10-28 (since deployed). Migration 0051 adds
  `trees.date_format`. It answers the backlog items "Dates read as GEDCOM
  everywhere" and the date half of "More app-wide settings" (ADR-054), as stage 1 of the reports
  plan ([reports-research.md](../reports-research.md)), because a printed or narrative report
  cannot say "born ABT 1900".

## Context

Epoch stores a date's original text (ADR-004) and showed it as written: "BET 1968 AND 1970",
"ABT 1900". That reads as jargon to a relative. The owner asked for day-month-year by default and
a per-tree choice of a few alternatives.

## Decision

- **Display only.** `displayDate` (`shared/date-display.ts`) turns stored text into words:
  "about 1900", "between 1968 and 1970", "3 March 1900". The stored text, edit fields, search,
  sorting, the change log's stored values and GEDCOM export are unchanged.
- **Nothing is reworded that cannot be read.** A phrase in brackets loses only its brackets. An
  `INT` date keeps its own words. Loosely typed text is read through `tidyDateText`, and anything
  still unreadable, including calendar escapes, is shown exactly as written. A dual year keeps its
  suffix ("30 January 1648/49").
- **Four formats, chosen per tree** by a manager in Tree settings, General (`trees.date_format`,
  default `day_month_year`):

  | Value | Example |
  |---|---|
  | `day_month_year` | 3 March 1900 |
  | `month_day_year` | March 3, 1900 |
  | `short` | 03 Mar 1900 |
  | `numeric` | 03/03/1900 (month first) |

  Years always have four digits. Two-digit years were asked about and left out: a tree spans
  centuries, so "03/03/00" cannot say whether it is 1900 or 2000.
- **Per tree, not per user.** Everyone reading a tree, and everything printed from it, reads dates
  the same way.
- **Components read the format from a context** (`components/date-format.ts`), set by the tree
  layout. This is a deliberate exception to "leaf components take props": the format is a
  locale-like preference every date-showing leaf needs. Outside a tree the default applies.
- **Server-composed text** (quality finding messages, change summaries) formats dates with the
  tree's setting where the service already has the tree.

## Consequences

- Tests that asserted GEDCOM text on screen assert words.
- The format rides on `ViewerScope`, which every read already builds from the tree row, so no
  page reads the tree twice for it.
- Stored change-log summaries and `tree-labels.ts` keep the dates they were written with. Edit
  fields, conflict rows and the date-spelling preview show the stored text on purpose.
- The person page's "(approximate)" badge is gone: "about" already says it.
- Name display order, the other half of ADR-054's deferred settings, is still open.
