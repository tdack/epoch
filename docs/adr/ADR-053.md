# ADR-053: One section order for the person page and drawer, evidence against claims, facts grouped by kind (amends ADR-028 and ADR-051)

## Status

Implemented

- **Status:** built on `claude/person-details-layout-2a8f7d` and deployed. No migration.
- **Context:** the person page and the tree drawer rendered the same sections in different orders, and the drawer showed every fact in full. A separate "Sources and evidence" section listed every citation a second time, against the same facts and names the page already showed them under.
- **Decision:**
  - **One section order.** Family, Facts, Names, Photos and documents, Privacy, Notes, Tasks, History. The drawer renders them in that order in one column. The page renders the same order in two columns: Family, Facts and Names on the wide left, the rest on the right, so reading the left column and then the right matches the drawer.
  - **Evidence sits against the claim it supports.** The "Sources and evidence" section is gone. Each fact, each name and each parent link shows its own citations, and the person's own citations show once, beneath the summary in the header. A claim with no citation reads Unsourced.
  - **Unsourced is the way to add a citation.** For an editor (or anyone who can cite), the Unsourced marker is a button that opens the citation dialog for that claim. A claim with citations keeps the disclosure, and a viewer sees the marker as plain text. The dialog's save and stale handling is shared (`citation-changes.ts`).
  - **Facts are grouped by kind, newest shown.** A group is one panel per fact type, with a custom event's sub-type as part of its kind. The panel shows its newest fact (undated counts as oldest; ties go to the later one in the list). The rest sit behind "Show N earlier", newest to oldest.
  - **A conflict never collapses.** If any fact in a group disagrees with or repeats another, every fact in that group is shown and the button is not drawn. The product does not hide disagreeing evidence.
- **Rejected alternatives:** keeping the evidence list and collapsing it by default (the duplicate would still be one click away, and a citation would still be listed in two places); collapsing a conflicting group (it would hide the disagreement the product is built to keep visible); grouping by a computed label, which would merge custom events that differ only by sub-type.
- **Consequences:** each parent in the person page DTO carries its `linkId` (threaded from the parent-child row through the relationship graph, optional there so older captured graphs still load), which is what the parent row files its evidence under. A fact's move controls swap only with a neighbour of the same kind and date, since the list now shows each kind as one panel.
