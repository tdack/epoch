# ADR-059: The person page opens on the newest of each attribute (amends ADR-058)

## Status

Implemented

- **Status:** built on `claude/person-page-full-layout-227778` and deployed. No migration.
- **Context:** ADR-058 listed every attribute under "Also recorded", in file order, below the Life timeline. A real record carries ten residences, three schools and two occupations, so the list was long, interleaved by kind, and below the fold, while what a reader wants first is where the person lives, what they studied and what they do.
- **Decision:**
  - **An "At a glance" section leads the left column,** above Life and Family. It shows one row per kind of attribute: the kind and its count in the heading column, its newest fact in the details. The rest sit behind "Show N earlier", newest to oldest, inline in the same row. It is not drawn for a person with no attributes.
  - **The drawer's grouping is shared, not copied.** `fact-groups.ts` holds the group key, label, newest-first order and group build (ADR-053) that both the drawer's panels and the page's rows use.
  - **A conflict still never folds.** A group with a disagreeing or repeated fact shows every member, as in the drawer.
  - **Life holds events only.** Events and partnership events stay oldest first with every one shown, so dated history is never behind a button. "Add fact" stays in Life, the one place that adds a fact.
  - **"Newest" is the newest recorded, never "current".** The heading says only the kind; nothing claims a person still lives or works there.
- **Rejected alternatives:** grouping repeated events such as census in Life (it would break the date order the timeline exists for); a "lives at / works as" line in the header (newest by start date is not current, above all for the dead or for a long-running period that started earlier); keeping "Also recorded" flat beneath Life.
- **Consequences:** ADR-058's "every fact is shown" now holds for events only. A move control in At a glance swaps with a same-date neighbour of the same kind, and up means newer, as in the drawer. A date written `FROM 1980` with no `TO` sorts from 1980 once saved; rows stored before the parser read open-ended periods keep a null sort key until re-derived (backlog).
