# ADR-025: Lint and format toolchain (architecture review §4, Phase A)

## Status

Implemented

- **Context:** AGENTS.md promises Prettier, a type-aware `@typescript-eslint/naming-convention` rule for booleans, Svelte-aware linting and a dead-code check, and none is installed (70 files use two-space indents, 285 use tabs). The Rust-based tools (oxlint, oxfmt, Vite+) are attractive, so they were checked against the docs on 2026-10-02 before the established tools were chosen.
- **Evidence, by question** (docs; none of the oxc/Vite+ claims below was exercised in this repo):
  1. **oxfmt and `.svelte`.** It lists Svelte as supported, but delegates to bundled Prettier and needs the `svelte` package and the `svelte` option ([language support](https://oxc.rs/docs/guide/usage/formatter/language-support.html)); only the `<script>` is formatted natively. It has `sortTailwindcss`, documented as "the same algorithm as prettier-plugin-tailwindcss" ([config reference](https://oxc.rs/docs/guide/usage/formatter/config-file-reference.html)). Whether that sorting reaches Svelte markup was not stated, and was not tried.
  2. **oxlint and `.svelte`.** It lints only the `<script>` blocks; it has no Svelte rules (no runes or a11y checks) ([linter overview](https://oxc.rs/docs/guide/usage/linter.html)). JS plugins (alpha) cannot load `eslint-plugin-svelte`: custom parsers such as Svelte are listed as unsupported ([JS plugins](https://oxc.rs/docs/guide/usage/linter/js-plugins.html)).
  3. **The boolean naming rule.** `naming-convention` with `types: ['boolean']` needs type information. oxlint's type-aware mode (tsgolint, stable, TypeScript 7) implements 60 of 62 targeted typescript-eslint rules, and `naming-convention` is one of the two that are not ([tsgolint README](https://github.com/oxc-project/tsgolint#implemented-rules)). JS plugins have no type information either. So oxlint cannot express the rule at all, and the smallest working set is a full ESLint with typescript-eslint beside it, for this rule alone.
  4. **Vite+** (1.0, MIT, [repo](https://github.com/voidzero-dev/vite-plus)). It claims SvelteKit support in general, but its docs say nothing on adapter-cloudflare, `getPlatformProxy`, `wrangler deploy workers/entry.ts`, the two-project Vitest config, or `nodeLinker`. It moves `dev`, `build`, `test` and `check` behind its own `vp` commands, and `lint` and `fmt` settings into `vite.config.ts`. It adds nothing for question 3, since it bundles the same oxlint. None of the build and deploy items could be verified without migrating the project.
- **Options:**
  - **A. oxlint + oxfmt + knip.** Cannot enforce the naming rule or lint Svelte; formatting `.svelte` still runs Prettier underneath. Fails two goals.
  - **B. Vite+ + knip.** Same linter gap as A, plus a migration of the dev, build and test entry points that AGENTS.md "Important Notes" 1–2 depend on, with the Cloudflare items unverified.
  - **C. Prettier (+ svelte and tailwindcss plugins) + ESLint flat config (typescript-eslint type-aware, eslint-plugin-svelte) + knip.** Meets every goal with documented, mature tools. Needs ESLint in any case (for 3 and for Svelte rules).
  - **Hybrids** (oxfmt for TS and Prettier for Svelte, or oxlint beside ESLint) each add a tool and still need ESLint and Prettier, to save time on a repository of about 350 files.
- **Decision:** option C. It is the one set with no moving part that exists only to be replaced: ESLint is required for the naming rule and Svelte rules whichever formatter is used, and Prettier is what AGENTS.md already documents and what the Tailwind and Svelte plugins target. One `npm run lint` runs the format check, ESLint and knip. `prettier-plugin-tailwindcss` is pointed at `src/app.css`, as Tailwind 4 has no config file to read.
- **Revisit when** (a) tsgolint implements `naming-convention`, and oxlint gains Svelte rules or a Svelte-capable JS-plugin parser (then ESLint can go and oxlint replace it), or (b) someone runs Vite+ in this repository through dev against local D1, build, `wrangler deploy workers/entry.ts --dry-run`, both Vitest projects and the e2e specs, and records the result. Until then neither is adopted.
- **Consequences:** Two more config files (`prettier`, `eslint`) and one for knip. ESLint's type-aware pass is slower than oxlint's would be (about 20 seconds over the repository); `npm run lint` is for the push gate, and `npm run format` and editor integration cover the edit loop. Knip reports as warnings until Phase B removes what it finds.
