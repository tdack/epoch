# ADR-076: Sub-trees and trees are reordered by dragging, saved as one batch (amends ADR-062)

## Status

Implemented

- **Status:** accepted and built on 2026-10-22 (not deployed). Migration 0040 adds
  `trees.position`.

## Context

A sub-tree moved up or down with two PATCHes, one per neighbour. They were two changes, so Undo
could revert only the second and left a tie; the manager offered no Undo for a move, and a failed
second PATCH left two sub-trees on one position (ADR-062). Trees had no order of their own: the
switcher listed a member's trees by `updated_at`, so the list shuffled whenever a tree was edited.

## Decision

- **A drag handle (⠿) at the start of each row** replaces the Up/Down buttons, in the sub-tree
  manager and on Administration › Trees. One component, `components/forms/ReorderHandle.svelte`,
  serves both; pointer events with capture, so mouse, pen and touch all drag. On the handle, the up
  and down arrow keys move the row one place, announced through a live region.
- **The whole new order is sent at once.** `PUT /api/trees/[id]/subtrees` takes every sub-tree with
  its version; the `reorder_subtrees` command writes positions `0..n-1` in one mutation, so it is one
  change in the log and record history (ADR-068) can undo it. The manager offers no Undo toast for
  it.
- **The tree order is the install owner's, for everyone.** `PUT /api/admin/tree-order` takes every
  tree id; `trees.position` orders the admin list, the switcher and Account › My trees. A new tree
  goes last. An order change does not bump a tree's `version` or `updated_at`, and is not in the
  change log, which records tree content (ADR-007).
- **Both refuse a stale set.** An order that misses or adds an id is a conflict (someone created or
  deleted one meanwhile), not something to guess around.

## Rejected alternatives

- *One PATCH that swaps two positions.* Closes the Undo gap for a move of one place, but a drag
  moves a row any distance, which is several swaps.
- *A per-member tree order on `tree_memberships`.* The owner wants one order everyone sees.

## Consequences

- **Given up:**
  - Dragging has no single-pointer alternative, a known and accepted failure of WCAG 2.2 2.5.7
    (Dragging Movements, AA). The arrow keys cover keyboard users (2.1.1).
  - The pointer drag is tested only through its pure helpers and the keyboard path, not in a
    browser.
